# 资源管理规范

> 自 2026-08-18 起用于约束新增和整理资源。

## 目标

- 网站仓库只保存发布所需资源，不保存封面母版、摄影原片和文章写作资料。
- 文件的扩展名必须与实际编码格式一致。
- 同一资源只保留一个发布版本，避免跨文章重复复制。
- 在保证阅读和高分屏显示质量的前提下，控制页面传输体积。
- 所有移动、重命名和转换都必须同步更新引用，并通过完整构建检查。

## 目录职责

```text
source/
├── pictures/
│   ├── site/       # 站点背景、头像、默认封面、错误页等界面资源
│   └── icons/      # favicon、PWA 图标等固定规格图标
└── _posts/
    ├── article.md
    └── article/    # 只属于该文章的封面、插图、截图和图表
```

- 站点界面资源不得散放在文章资源目录。
- 只被一篇文章使用的图片留在对应的文章资源目录。
- 每篇文章的封面独立保存在对应文章资源目录中；即使多篇文章使用相同画面，也分别保留一份发布版本，方便随文章一起维护。
- favicon 和 PWA 图标保留所需的多个固定尺寸，不按普通重复文件处理。
- 不被网站引用但需要留存的文件，不要上传至云端。

## 文件命名

- 新文件使用小写英文、数字和短横线，不使用空格。
- 文章本地封面统一命名为 `cover.<ext>`。
- 正文插图使用能够说明内容的名称，例如 `studio-workflow.webp`。
- 不使用缺乏语义的 `image.png`、`1.jpg` 或哈希式名称；历史文件逐步改名。
- 扩展名必须反映真实编码：PNG 使用 `.png`，JPEG 使用 `.jpg`，WebP 使用 `.webp`。

## 格式选择

- 摄影、绘画、背景和专辑封面：优先使用 WebP。
- 界面截图、带小字图片：优先使用 WebP lossless；文字清晰度不合格时保留 PNG。
- 需要透明背景的 Logo：保留 PNG；若有可靠矢量源，可另行采用 SVG。
- favicon 和 PWA 图标：按浏览器规范保留 ICO/PNG。
- GIF 仅用于确实需要动画的内容；静态 GIF 应转换为 PNG 或 WebP。
- 不为了格式统一而重复转码已经体积合理的有损图片。

## 尺寸与体积目标

| 用途 | 建议尺寸 | 目标体积 |
| --- | --- | ---: |
| 头像 | 512 × 512 | 不超过 100 KiB |
| 方形文章封面 | 1200 × 1200；确有放大需求时不超过 1600 × 1600 | 不超过 500 KiB |
| 横幅、背景图 | 最长边不超过 1920 px | 不超过 600 KiB |
| 正文摄影或插画 | 最长边不超过 1600 px | 不超过 500 KiB |
| 需要放大的截图 | 最长边不超过 1920 px | 原则上不超过 800 KiB |
| favicon/PWA 图标 | 使用规定尺寸 | 不适用普通上限 |

- 超过上述目标不直接视为错误，但应说明保留高分辨率或高质量的理由。
- 仓库中不保留 3000–4000 px 的出版母版；母版保存在站点仓库之外。

## 推荐编码参数

- 普通摄影、插画和背景：WebP quality 80–82。
- 包含细小文字或高对比线条的封面：WebP quality 84–88。
- 截图：WebP lossless，或者在人工对比后使用高质量有损编码。
- 转换时移除对网页无用的 EXIF、缩略图和编辑软件元数据。
- 不允许只修改文件后缀而不转换编码。

## 例外

- 历史图片逐步迁移。
- 引用来源、版权信息或原文件名具有辨识价值时，可以保留原文件名。
- 需要下载原尺寸的作品应作为明确的下载资源提供，不与页面展示图混用。
- Git 历史中的大文件不在普通资源整理中清除；如需压缩仓库历史，应另行评估并单独执行。
