`Rolling Pebble v0.8.0` 已经发布，可以在 [GitHub Releases](https://github.com/Harmonese/rollingpebble/releases/tag/v0.8.0) 查看和下载。这次更新把歌词翻译、项目保存和自动打轴之后的审阅流程补了起来。

之前的版本主要在整理工作站的接口与模块边界。到了 0.8，我们希望一首歌从导入、编辑、翻译到打轴和保存，能够在同一个工作区里持续完成。

## 核心变化

### 歌词翻译与双栏编辑

现在可以通过本地或云端的 OpenAI 兼容服务翻译歌词，支持整首翻译、单行重译、自定义翻译指令和取消请求。凭据优先保存在系统钥匙串中；无法使用时，需要明确选择仅在当前会话保存。翻译也有独立的代理设置。

原文和译文使用两个连续的 LRC 编辑区，支持同步滚动、换行对齐，以及分别复制和下载。译文共享原文的时间轴，在 Synchronizer 中显示在原文下方。

编辑原文后，对应译文会被标记为需要检查；遇到无法明确对应的行结构变化，也会先要求确认。翻译完成后再改歌词，是工作过程中很常见的事，我们希望这一步不会悄悄打乱已经整理好的对应关系。

### 自动保存与恢复工作区

项目首次保存之后会自动保存，也可以使用 Ctrl/Command+S 手动触发。界面会显示保存状态，失败后可以重试。

恢复工作区会保留待处理的音频、翻译和尚未完成的编辑文本。桌面端关闭或退出时，会等待保存完成，或者由用户明确放弃。保存流程也加入了中断恢复，避免歌词、译文和元数据出现一部分新、一部分旧的情况。

这次还加入了 New Project 和 Replace Audio。替换音频时，属于音频的元数据会随之更新，手动填写和导入的字段则受到保护，包括刻意留空的值。

### 独立的 Auto Timing Review

自动打轴结果现在先进入独立审阅区，不会直接覆盖项目歌词。审阅草稿可以保存、编辑、导出 LRC，也支持部分应用和查看结果历史。替换音频之后，旧审阅会转为只读，仍然可以保留作参考。

这一版接入 `py-roller 0.10.2 / Protocol v2`。Auto Timing 仍然是实验功能，当前只支持英语；新安装默认使用 Ordered 模式，无法解决的歌词会保留下来，交给人工继续打轴。串行批处理也支持失败项重试和中断后明确继续。

### 桌面环境与模型管理

macOS arm64 桌面包内置 Python 3.12.15、FFmpeg 和经过哈希校验的引擎依赖，组件准备可以离线自动完成，不再要求用户自己安装编译器或 Homebrew。模型权重仍需要明确下载。

模型管理支持 ModelScope 和官方来源、代理、断点续传、实际字节进度与针对性修复。启动时会离线校验已安装模型，报告缺失、损坏或不可读的问题。项目、恢复数据、运行环境、结果和缓存也归入统一的应用存储目录。

## 下载与使用

本次桌面发行面向 macOS arm64，需要 macOS 14 或更新版本，采用 ad-hoc 签名，尚未经过 Apple 公证。其他桌面平台仍未完成验证。Python 发行包包含后端和 WebUI，不包含桌面专用的解释器、引擎依赖包和模型权重。

欢迎试用这一版，尤其是翻译之后继续修改原文、替换音频、恢复未完成项目和审阅打轴结果这些流程。如果遇到问题，可以通过 [GitHub Issues](https://github.com/Harmonese/rollingpebble/issues) 反馈。
